## Phase 1

- **EDA missingness:** Preserve source `?` values as missing in the processed table, report missing counts, and do not drop rows or impute during EDA. This keeps all 303 records available and avoids fitting imputation statistics before the training split. Histograms omit missing values within each feature; the correlation matrix uses pairwise complete observations. Fit any later imputer only on training data as part of the model pipeline.
- **Target:** Map original Cleveland `num=0` to absence (`0`) and `num=1,2,3,4` to presence (`1`); reject target values outside this defined domain.
- **EDA scope:** Plot histograms for the 13 numeric clinical features (not the outcome), use Pearson correlations across those features, and show class counts after binarization.
- **Reproducibility:** Download the processed Cleveland file from the UCI URL documented in `docs/DATA.md`; retain its local raw copy and record its download date. Pin only the pandas and matplotlib dependencies needed by this phase; extend the manifest when later phases need their dependencies.
- **Alternatives considered:** Dropping incomplete patient rows would discard six otherwise usable records; imputing now would estimate values before a train/test split. Retaining missing cells and reporting per-column counts preserves source evidence without leakage; modeling-time imputation remains for the training pipeline. Plotting targets among the clinical-feature histograms would mix outcome and predictor distributions, so the target is instead shown separately in the class-balance chart. The source is the UCI repository rather than a repackaged dataset so the download remains traceable to the assigned dataset.

## Phase 2

- **Candidate algorithms:** Compare Logistic Regression, Random Forest, and RBF-kernel Support Vector Classification (SVC). Logistic Regression provides a regularized linear baseline; Random Forest can model nonlinear splits and interactions; RBF SVC tests a smooth nonlinear boundary on this small tabular dataset. These give a linear baseline and two distinct nonlinear alternatives, as required, without assuming one family will win. No external implementation is copied; use the official scikit-learn estimator APIs.
- **Feature preprocessing:** Treat `age`, `trestbps`, `chol`, `thalach`, and `oldpeak` as continuous numeric measurements; median-impute within a fold and standardize them. Treat `sex`, `cp`, `fbs`, `restecg`, `exang`, `slope`, `ca`, and `thal` as coded categorical values; impute the most frequent value within a fold and one-hot encode with unknown categories ignored. This avoids imposing artificial distances/order on nominal clinical codes and keeps inference preprocessing inside the fitted pipeline. The target `num` is excluded from features.
- **Validation:** Use five-fold stratified cross-validation, shuffled with fixed `random_state=42`, for every candidate; return accuracy, precision, recall, and ROC-AUC as fold means and standard deviations. Shuffling with a recorded seed provides repeatable, class-preserving partitions; five folds retain a useful validation set size for the 303-row dataset.
- **Champion rule:** Maximize mean recall first because missed positive disease cases are the most costly screening error; break recall ties by mean ROC-AUC (ranking/discrimination), then mean precision. Report accuracy too, but do not select on accuracy alone. This is a model-comparison rule for this assignment, not a clinical deployment claim.
- **Alternatives considered:** A single train/test split would make model ranking depend heavily on one small sample; stratified folds use the limited data more efficiently while preserving both classes. Standardizing all numeric codes would falsely treat nominal categories as equally spaced measurements; one-hot encoding avoids that. Selecting by accuracy alone can obscure false negatives, so recall is primary and ROC-AUC and precision are tie-breakers. The scikit-learn `Pipeline`, `ColumnTransformer`, `StratifiedKFold`, and `cross_validate` interfaces guide the implementation; see the official [compose API](https://scikit-learn.org/stable/modules/compose.html), [cross-validation API](https://scikit-learn.org/stable/modules/cross_validation.html), and [metrics API](https://scikit-learn.org/stable/modules/model_evaluation.html).
- **Confidence for the later prediction artifact:** Wrap the full preprocessing-plus-RBF-SVC pipeline in scikit-learn `CalibratedClassifierCV` with sigmoid (Platt) calibration, five stratified folds, shuffle, and `random_state=42`; use `ensemble=True` and average the calibrated folds' probabilities. At inference, choose the label with the highest class probability and expose that probability as `confidence`. Keep calibration inside the artifact so inference has the same fitted preprocessing. Before describing the values as calibrated, evaluate Brier score and a reliability curve using out-of-fold predictions. This is a probability estimate, not clinical certainty.
- **Confidence alternatives considered:** Raw SVC decision scores are not probabilities and cannot safely be labeled confidence. SVC's built-in probability mode uses an internal calibration procedure but hides more of the calibration design. The explicit scikit-learn calibrator makes the calibration method and stratified folds inspectable and allows the entire preprocessing/model pipeline to remain inside each calibration fold. This is a plan for artifact packaging; no confidence-bearing artifact is created in Phase 2.

## Phase 3

- **Tracking integration:** The existing training command will create one MLflow run per evaluated candidate in experiment `heart-disease-2025ae05142`. Use an absolute SQLite URI pointing to repository-local `mlflow.db` and an explicit file artifact location under repository-local `mlruns/`. This avoids accidental remote tracking via environment defaults and requires no server or cloud account. Ignore the database, SQLite sidecars, and artifact directory in git; keep the human-readable run summary in `reports/mlflow_summary.md`.
- **Run evidence:** Each run records `author=2025ae05142`, model name, champion flag, dataset SHA-256, row count, feature schema, estimator and preprocessing parameters, CV folds/seed, four mean CV metrics and their standard deviations. Log the fitted full preprocessing-plus-classifier pipeline with an input signature and example, the three required EDA figures, and the comparison report. Use explicit Python logging with author attribution for MLflow messages rather than suppressing errors.
- **Registry:** Register the selected fitted pipeline as `heart-disease-champion-2025ae05142`; keep its run ID, model URI, and registry version in the generated summary. Additional training executions create new runs and registry versions rather than overwrite prior experiment evidence.
- **Scope and alternatives:** Native MLflow sklearn artifacts preserve preprocessing and signatures better than logging a bare estimator or only a pickle file. SQLite supports the local registry whereas a flat file tracking backend would not meet the required backend choice. The Phase 3 registered RBF SVC is the uncalibrated Phase 2 classifier: it supports labels/decision scores, not confidence probabilities. Calibration, nested out-of-fold probability validation, and packaging the resulting confidence-capable artifact remain Phase 4; do not silently substitute it while claiming the Phase 2 CV metrics still describe the calibrated model. API reference: [MLflow sklearn](https://mlflow.org/docs/latest/api_reference/python_api/mlflow.sklearn.html) and [tracking](https://mlflow.org/docs/latest/ml/tracking/).
- **Serialization compatibility probe:** MLflow 3.17.1's default skops serializer rejected `numpy.dtype` in the fitted pipeline. Explicitly use MLflow's supported `cloudpickle` format for these locally trained artifacts rather than broadening skops trust lists. Load only artifacts produced by this trusted local training flow: pickle-based formats can execute code when loaded. Disable MLflow telemetry before import; tracking stays local.

## Phase 4

- **Decision threshold:** Predict 1 when P(disease) > 0.5; otherwise predict 0. With classes ordered `[0, 1]`, argmax breaks an exact probability tie in favor of class 0, returning confidence 0.5. This documents existing behavior, not a threshold change or a clinically optimized cutoff.

- **Confidence artifact:** Recompute the established candidate comparison on the input data and apply the same champion rule, rather than hardcoding the winner from a report. Wrap the selected full preprocessing/classifier pipeline in sigmoid `CalibratedClassifierCV` with five shuffled stratified folds, seed 42, and `ensemble=True`. Store the calibrator in a sklearn `Pipeline`; its fitted inner pipelines own all imputation, encoding, and scaling. Persist the complete object with joblib at `models/heart_pipeline.joblib`, plus JSON provenance (data/artifact hashes, versions, feature names, calibration settings, and selected candidate). Only load locally produced trusted joblib artifacts.
- **Calibration validation:** Use five outer stratified folds and five inner calibration folds so no outer validation row participates in model fitting, preprocessing, or calibration. Report pooled out-of-fold classification metrics, Brier score, log loss, a training-fold prevalence baseline, and a reliability diagram with bin counts. Candidate selection used the same dataset in Phase 2, so these are post-selection diagnostics, not an unbiased final test or a clinical calibration guarantee. Fit the final confidence pipeline on all available rows only after obtaining out-of-fold predictions. Probability-based labels may differ from the uncalibrated Phase 3 SVC; report new metrics separately, never overwrite the original comparison.
- **Inference contract:** `predict_records(records)` accepts a non-empty JSON-style list of feature dictionaries with exactly the 13 feature names; values must be finite numbers or `None` (imputed by the fitted pipeline). Reject missing/extra keys, booleans, strings, non-finite numbers, missing artifacts, or malformed model outputs explicitly. Do not refit, download, or access MLflow while predicting. Return integer `prediction` (0/1) and float `confidence`, the probability of the returned class, as a list of dictionaries. Use the documented repository-local artifact path; CLI prints only JSON to stdout and attributed errors to stderr.
- **Reproducibility and scope:** Pin numerical and serialization dependencies as well as the existing top-level stack, validate in a fresh isolated `.venv-phase4` without system site packages, and keep generated model binaries/venvs out of git. The candidate training command continues to log the three original pipelines to MLflow; the separate packaging command creates the validated confidence artifact and calibration report without relabeling the existing uncalibrated registry version. A new calibrated registry version can be introduced explicitly later; serving uses the packaged artifact. Alternatives were bare-estimator export (preprocessing drift), raw SVC margins (not probabilities), and in-sample calibration assessment (optimistic leakage). Reference: [scikit-learn probability calibration](https://scikit-learn.org/stable/modules/calibration.html).

Regenerate preprocessing and EDA from the committed source snapshot to avoid making every CI run depend on UCI availability. Test the downloader independently with local response fixtures. Training runs actual MLflow logging/registration in the runner's local SQLite/file store, packages the separate calibrated artifact, verifies inference, and uploads evidence for seven days with read-only repository permissions. CI does not deploy, commit generated outputs, or use cloud credentials.
- **Hosted evidence:** Local success and workflow syntax checks are not proof of a hosted Actions run. Do not push or dispatch without the student's explicit request. Record hosted execution as pending until the workflow is published and a run is observed.

## Phase 6

- **Serving contract:** Add a FastAPI `GET /health` endpoint returning `{"status":"ok"}` and `POST /predict`, which accepts the same non-empty JSON list of feature records as the CLI and returns the same list of `{prediction, confidence}` objects. Reuse `predict_records` so its exact-key, finite-number, class-order, and trusted-artifact checks remain authoritative; map invalid request data to HTTP 422 and do not disguise missing artifacts or unexpected inference failures as successful predictions.
- **Container boundary:** Before building, generate the packaged model locally with `python -m src.train.package`; the image build requires that locally generated `models/heart_pipeline.joblib` artifact, which remains gitignored and is not committed. Build an inference-only image from `python:3.12-slim`, install a separate pinned `requirements-serving.txt` containing the artifact's recorded numerical-library versions plus FastAPI/Uvicorn, and copy only the API source and generated model. This avoids installing training/MLflow/EDA dependencies in the runtime image and avoids retraining or downloading data during startup. Run Uvicorn on `0.0.0.0:8000` as a non-root user; publish the port only to VM loopback for the smoke test.
- **Alternatives and rationale:** Reusing the CLI validation avoids a second, potentially divergent input contract. Training on container startup would make startup slow and results dependent on mutable data/environment; mounting an arbitrary host model would weaken artifact reproducibility; installing the complete training requirements would unnecessarily enlarge the serving image. The design is an original implementation of this repository's existing inference contract; no third-party student implementation or Dockerfile is adapted.
